Javavoid serve() {
    while (!listener.isClosed()) {
        try (Socket connected = listener.accept()) {  // một kết nối tại một thời điểm
            connected.setSoTimeout(5_000);  // read timeout: client không gửi gì quá 5 giây
            log.println("accepted " + fourTuple(connected));
            int requests = handle(connected);  // phục vụ đến khi client đóng chiều gửi
            log.println("closed, requests: " + requests);
        } catch (IOException e) {  // gồm cả SocketTimeoutException: lỗi của một kết nối không dừng server
            log.println("connection error: " + e.getMessage());
        }
    }
}

Vòng lặp trong: mỗi dòng nhận được là một khóa, trả đúng một dòng

Javaint handle(Socket connected) throws IOException {
    var in = new BufferedReader(new InputStreamReader(connected.getInputStream(), UTF_8));
    var out = new BufferedWriter(new OutputStreamWriter(connected.getOutputStream(), UTF_8));
    int requests = 0;
    for (String key; (key = in.readLine()) != null; requests++) {  // null: client đã đóng chiều gửi
        out.write(reply(key) + "\n");  // OK <giá trị>, NOTFOUND hoặc ERR <lý do>
        out.flush();
    }
    return requests;
}

    src/netlab/lookup/LookupServer.java
    void serve() {
    while (!listener.isClosed()) {
        try (Socket connected = listener.accept()) {  // một kết nối tại một thời điểm
            connected.setSoTimeout(5_000);  // read timeout: client không gửi gì quá 5 giây
            log.println("accepted " + fourTuple(connected));
            int requests = handle(connected);  // phục vụ đến khi client đóng chiều gửi
            log.println("closed, requests: " + requests);
        } catch (IOException e) {  // gồm cả SocketTimeoutException: lỗi của một kết nối không dừng server
            log.println("connection error: " + e.getMessage());
        }
    }
}

    Mã của vòng lặp ngoài nằm trong phương thức serve. Lời gọi accept đặt trong khối try-with-resources, nên connected socket luôn được đóng khi phục vụ xong. Server đặt read timeout 5 giây cho kết nối, ghi log 4-tuple, rồi chuyển kết nối cho phương thức handle. Khối catch bắt IOException, kể cả SocketTimeoutException, nhờ đó lỗi ở một kết nối chỉ kết thúc kết nối ấy, còn server vẫn chạy tiếp. Mình chạy server, rồi chạy ba client nối tiếp nhau. Trong log, mỗi dòng accepted đi kèm dòng closed của chính kết nối đó, rồi kết nối sau mới được nhận.

    Slide 5. Vòng lặp trong: mỗi dòng nhận được là một khóa, trả đúng một dòng

    src/netlab/lookup/LookupServer.java
    int handle(Socket connected) throws IOException {
    var in = new BufferedReader(new InputStreamReader(connected.getInputStream(), UTF_8));
    var out = new BufferedWriter(new OutputStreamWriter(connected.getOutputStream(), UTF_8));
    int requests = 0;
    for (String key; (key = in.readLine()) != null; requests++) {  // null: client đã đóng chiều gửi
        out.write(reply(key) + "\n");  // OK <giá trị>, NOTFOUND hoặc ERR <lý do>
        out.flush();
    }
    return requests;
}

    Còn vòng lặp trong nằm ở phương thức handle. Hai stream BufferedReader và BufferedWriter dùng UTF-8, như ở phần về charset và framing của Chương 1. Mỗi vòng đọc một dòng làm khóa, chuyển khóa cho phương thức reply để tính phản hồi, rồi ghi phản hồi kèm ký tự LF. Lời gọi flush đứng ngay sau, vì client đang chờ phản hồi này rồi mới gửi yêu cầu tiếp. Phương thức reply trả về một trong ba dạng của đặc tả: OK kèm giá trị, NOTFOUND, hoặc ERR kèm lý do. Để kiểm chứng, client đầu tiên gửi lần lượt các trường hợp thử của đặc tả. Các bạn đoán trước dòng dài 300 byte nhận phản hồi gì. Kết quả: hai khóa hanoi và huế, khóa có dấu, đều có giá trị, còn atlantis không có. Dòng rỗng và dòng 300 byte nhận đúng hai mã lỗi của đặc tả.

    Lưu ý dựng: Mã phía trên, kết quả của client phía dưới. Highlight dòng readLine() rồi dòng reply(key) khi đọc tới. Phương thức reply (mười dòng, ánh xạ ba dạng phản hồi và hai mã lỗi) ở README của mã, không đưa lên slide. Hiện dần: bước 1 khi đọc “Kết quả: hai khóa”.

    Slide 7. Một client không gửi gì làm mọi client sau phải chờ

    Câu hỏi tương tác 1

    Câu hỏi đầu dùng lại bảng 4-tuple của ba kết nối.

    Câu hỏi: Ba client trên cùng một máy kết nối lần lượt tới server tra cứu ở port 9199. Ba kết nối được phân biệt bằng gì?
    • A. Bằng 4-tuple: địa chỉ và port của hai đầu; ở đây ba kết nối khác nhau ở port client.
    • B. Server cấp cho mỗi kết nối một port mới sau khi accept.
    • C. Bằng thứ tự gọi accept: kết nối thứ nhất, thứ hai, thứ ba.
    • D. Bằng địa chỉ IP của client.
    Đáp án đúng: A — Một kết nối TCP được định danh bằng 4-tuple. Cả ba kết nối có local port 9199 và cùng địa chỉ 127.0.0.1 ở hai đầu; chỉ port client (ephemeral port) khác nhau. Server không cấp port mới cho kết nối.

    Đáp án là A. Phương án B là hiểu nhầm phổ biến, nhưng log cho thấy cả ba kết nối đều có local port 9199: server không cấp port mới cho kết nối. Phương án D cũng không đủ, vì ba client chạy trên cùng một máy, cùng địa chỉ 127.0.0.1.

    Câu tiếp theo đặt các bạn vào vị trí client đến sau một client chậm.

    Câu hỏi: Một client kết nối tới server tra cứu tuần tự nhưng không gửi dòng nào. Vì sao các client đến sau phải chờ?
    • A. Backlog chỉ chứa được một kết nối.
    • B. Kết nối của các client sau bị từ chối (connection refused) cho đến khi client đầu đóng.
