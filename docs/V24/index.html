Server SOAP: vài chú thích và một lời gọi publish

Java@WebService(serviceName = "TempConvert", targetNamespace = "http://netlab/tempconvert")
public class TempConvert {
    @WebMethod
    public double celsiusToFahrenheit(@WebParam(name = "celsius") double celsius) {  // thao tác và tên tham số trong message
        return celsius * 9 / 5 + 32;
    }
}

    Slide 1. Gọi dịch vụ từ ngôn ngữ khác: cần hợp đồng và message chung

    • RMI: stub, serialization, giao thức đều là cơ chế **riêng của Java**
    • Cần một **hợp đồng** mô tả thao tác và kiểu dữ liệu, không phụ thuộc ngôn ngữ
    • Cần một **định dạng message** mọi ngôn ngữ đọc được, truyền qua giao thức sẵn có: **HTTP**
    Trọng tâm: **Câu hỏi của phần:** SOAP message có cấu trúc thế nào, và WSDL mô tả dịch vụ ra sao để ngôn ngữ nào cũng gọi được?

    Với RMI, mọi thứ giữa hai đầu đều là cơ chế riêng của Java: stub do JDK sinh, tham số đi qua serialization của Java, và giao thức truyền cũng chỉ RMI runtime hiểu. Để ngôn ngữ khác gọi được, lời gọi từ xa cần hai thứ. Thứ nhất là một hợp đồng mô tả dịch vụ có những thao tác nào, tham số và kết quả thuộc kiểu gì, viết ở dạng không phụ thuộc ngôn ngữ. Thứ hai là một định dạng message mà ngôn ngữ nào cũng đọc được, truyền qua một giao thức có ở mọi nơi là HTTP. Dịch vụ cung cấp thao tác theo cách đó gọi là web service, hay dịch vụ gọi qua giao thức web. SOAP và WSDL là cặp chuẩn đầu tiên cho loại dịch vụ này: SOAP quy định message, còn WSDL mô tả hợp đồng. Vậy SOAP message có cấu trúc thế nào, và WSDL mô tả dịch vụ ra sao để ngôn ngữ nào cũng gọi được?

    Slide 2. SOAP message: Envelope bọc Header và Body, đi trong một HTTP POST

    Kết luận:
    • **SOAP**: lời gọi và kết quả là message **XML**; **SOAP envelope** chứa Header tùy chọn và Body mang thao tác, tham số.

    Vế thứ nhất là cấu trúc message. SOAP là giao thức đóng gói lời gọi và kết quả thành message XML, hay ngôn ngữ đánh dấu mở rộng, thường truyền qua HTTP. Mình minh họa bằng TempConvert, dịch vụ đổi nhiệt độ hay gặp trong tài liệu về web service. Các bạn nhìn request ở bên trái: đó là một HTTP POST tới đường dẫn tempconvert, với kiểu nội dung text/xml. Thân request là SOAP envelope, phần tử gốc của message, gồm phần Header tùy chọn cho các thông tin như bảo mật hay giao dịch, và phần Body. Phần Body mang lời gọi: phần tử celsiusToFahrenheit cho biết tên thao tác, đổi độ C sang độ F, còn phần tử con celsius chứa tham số, giá trị 100. Response ở bên phải có cùng cấu trúc, và Body của nó chứa kết quả 212 trong phần tử return. Ở cả hai chiều, XML thay cho serialization của Java, vì đây là dạng văn bản mà ngôn ngữ nào cũng có thư viện đọc ghi.

    Lưu ý dựng: Hình soap-message: ba bước của hình, bước 4 là ô kết luận. Hiện dần: bước 1 khi đọc “Các bạn nhìn request”; bước 2 khi đọc “Phần Body mang lời gọi”; bước 3 khi đọc “Response ở bên phải”; bước 4 khi đọc “Ở cả hai chiều”.

    Slide 3. WSDL là hợp đồng: từ đó mỗi ngôn ngữ tạo stub riêng

    Kết luận:
    • **WSDL** mô tả thao tác, kiểu dữ liệu và endpoint; công cụ của từng ngôn ngữ đọc WSDL để tạo stub.

    Client ở ngôn ngữ khác biết phải gửi message như thế nào nhờ WSDL, hay Web Services Description Language, tài liệu XML mô tả web service. Server tự sinh WSDL và công bố ngay tại endpoint. Hai phần đầu mô tả dịch vụ có gì. Phần types định nghĩa kiểu dữ liệu, ở đây là phần tử celsiusToFahrenheit với trường celsius kiểu số thực double. Phần portType liệt kê các thao tác, mỗi thao tác có message vào và message ra. Hai phần sau mô tả gọi bằng gì và ở đâu: phần binding chọn SOAP qua HTTP, phần service ghi địa chỉ endpoint. Từ cùng một WSDL, mỗi ngôn ngữ có công cụ tạo stub: Java có công cụ wsimport, C# có công cụ dotnet-svcutil, còn thư viện zeep của Python đọc WSDL ngay lúc chạy. Như vậy, vai trò của remote interface trong RMI được thay bằng WSDL, một hợp đồng không gắn với ngôn ngữ nào.

    Lưu ý dựng: Hình wsdl-hop-dong: ba bước của hình, bước 4 là ô kết luận. Hiện dần: bước 1 khi đọc “Hai phần đầu”; bước 2 khi đọc “Hai phần sau”; bước 3 khi đọc “Từ cùng một WSDL”; bước 4 khi đọc “Như vậy”.

    Slide 4. Server SOAP: vài chú thích và một lời gọi publish

    src/main/java/netlab/soap/TempConvert.java
    @WebService(serviceName = "TempConvert", targetNamespace = "http://netlab/tempconvert")
public class TempConvert {
    @WebMethod
    public double celsiusToFahrenheit(@WebParam(name = "celsius") double celsius) {  // thao tác và tên tham số trong message
        return celsius * 9 / 5 + 32;
    }
}

    Mình dựng dịch vụ TempConvert bằng Jakarta XML Web Services, bộ API chuẩn cho SOAP. Từ JDK 11, API này không còn nằm sẵn trong JDK, nên mình lấy bản hiện thực Metro qua Maven. Trong lớp TempConvert trên slide, mình chỉ thêm chú thích WebService cho lớp và chú thích WebMethod cho phương thức. Chú thích WebParam đặt tên celsius cho tham số trong message, và thao tác ngược lại, fahrenheitToCelsius, viết theo cùng cách. Để dịch vụ chạy, một lớp khởi động nhỏ ngoài slide, SoapServer, gọi phương thức publish của lớp Endpoint với địa chỉ của dịch vụ, port 9199, đường dẫn tempconvert. Từ đó, Metro nhận request bằng HTTP server có sẵn trong JDK, tự đọc message XML và gọi phương thức Java, nên mình không viết dòng nào đọc hay ghi XML. Log của server in địa chỉ endpoint, địa chỉ WSDL, và một lời gọi celsiusToFahrenheit với giá trị 100 gửi tới từ curl.

    Lưu ý dựng: Mã phía trên, log của server phía dưới. Highlight @WebService, @WebMethod, @WebParam theo lời đọc. Hiện dần: bước 1 khi đọc “Log của server”.

    Slide 5. Gửi SOAP request bằng curl và đọc response XML

    request.xml
    <soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/" xmlns:tc="http://netlab/tempconvert">
  <soap:Body>
    <tc:celsiusToFahrenheit>
      <celsius>100</celsius>
    </tc:celsiusToFahrenheit>
  </soap:Body>
</soap:Envelope>

    Vì SOAP chỉ là XML trong một HTTP POST, curl gửi được request mà không cần stub nào. File request.xml chứa SOAP envelope có Body là phần tử celsiusToFahrenheit với giá trị 100. Namespace của phần tử này phải khớp targetNamespace của dịch vụ, đúng như WSDL đã mô tả. Mình gửi file này bằng curl, với header Content-Type là text/xml, rồi định dạng lại response cho dễ đọc. Các bạn thử đoán: để gửi con số 100, chỉ dài 3 byte, request SOAP dài bao nhiêu byte? Kết quả: mã trạng thái 200, và phần tử return trong envelope trả về mang giá trị 212, đúng 100 độ C đổi sang độ F. Kích thước mới là điều đáng chú ý: request dài 242 byte, response dài 259 byte, chưa kể header HTTP.

    Lưu ý dựng: XML request phía trên, kết quả phía dưới. Sau câu "dài bao nhiêu byte", dừng khoảng 2 giây trước khi khung kết quả hiện. Highlight <celsius>100</celsius> trong request, <return> và dòng kích thước trong kết quả. Hiện dần: bước 1 khi đọc “Kết quả”.

    Để độc lập với ngôn ngữ, SOAP phải trả ba cái giá.     Tổng kết

    • **Web service**: thao tác gọi qua HTTP, message và hợp đồng không phụ thuộc ngôn ngữ
    • **SOAP**: message **XML**; **SOAP envelope** gồm Header tùy chọn và Body mang thao tác, tham số
    • **WSDL**: hợp đồng mô tả thao tác, kiểu dữ liệu, endpoint; mỗi ngôn ngữ tạo stub từ WSDL

    Web service đưa lời gọi từ xa ra ngoài một ngôn ngữ: thao tác được gọi qua HTTP, với message và hợp đồng không phụ thuộc ngôn ngữ. Với SOAP, lời gọi và kết quả là message XML, trong đó SOAP envelope gồm Header tùy chọn và Body mang thao tác cùng tham số. WSDL đóng vai hợp đồng, mô tả thao tác, kiểu dữ liệu và endpoint, để mỗi ngôn ngữ tạo stub riêng. Năm từ khóa đi cùng SOAP là web service, SOAP, SOAP envelope, WSDL và XML.
