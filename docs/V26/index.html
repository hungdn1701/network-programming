File .proto: dịch vụ, RPC unary và message có số trường

Protobufservice Lookup {
  rpc Lookup (LookupRequest) returns (LookupReply);  // unary: một request, một response
}

message LookupRequest {
  string key = 1;  // số trường 1: định danh trường khi mã hóa, không được đổi
}

message LookupReply {
  bool found = 1;
  string value = 2;
}
  • service, rpc: dịch vụ và lời gọi unary
  • message: mỗi trường có kiểu, tên và số trường
  • Không có khóa: found bằng false; trường không gán mang giá trị mặc định

Server: kế thừa lớp cơ sở sinh ra, trả kết quả qua StreamObserver

Javastatic final class LookupService extends LookupGrpc.LookupImplBase {
    @Override
    public void lookup(LookupRequest request, StreamObserver<LookupReply> responseObserver) {
        String value = DATA.get(request.getKey());
        LookupReply reply = LookupReply.newBuilder()
                .setFound(value != null)
                .setValue(value != null ? value : "")
                .build();
        responseObserver.onNext(reply);  // unary: gửi đúng một response
        responseObserver.onCompleted();  // rồi kết thúc lời gọi

    Kết luận:

    Slide 4. File .proto: dịch vụ, RPC unary và message có số trường

    • `service`, `rpc`: dịch vụ và lời gọi **unary**
    • `message`: mỗi trường có kiểu, tên và **số trường**
    • Không có khóa: `found` bằng false; trường không gán mang giá trị mặc định
    src/main/proto/lookup.proto
    service Lookup {
  rpc Lookup (LookupRequest) returns (LookupReply);  // unary: một request, một response
}

message LookupRequest {
  string key = 1;  // số trường 1: định danh trường khi mã hóa, không được đổi
}

message LookupReply {
  bool found = 1;
  string value = 2;
}

    Khối service khai báo một RPC kiểu unary, tức một request và một response, như mọi lời gọi từ đầu chương. Hai khối message khai báo trường của request và của reply: mỗi trường có kiểu, tên và số trường; số trường được ghi vào tag, nên đã dùng thì không được đổi. Khóa không tồn tại được báo bằng trường found bằng false; phiên bản 3 của Protocol Buffers không có giá trị null, trường nào không gán thì mang giá trị mặc định, như chuỗi rỗng hay false.

    Slide 5. Server: kế thừa lớp cơ sở sinh ra, trả kết quả qua StreamObserver

    src/main/java/netlab/grpc/LookupServer.java
    static final class LookupService extends LookupGrpc.LookupImplBase {
    @Override
    public void lookup(LookupRequest request, StreamObserver<LookupReply> responseObserver) {
        String value = DATA.get(request.getKey());
        LookupReply reply = LookupReply.newBuilder()
                .setFound(value != null)
                .setValue(value != null ? value : "")
                .build();
        responseObserver.onNext(reply);  // unary: gửi đúng một response
        responseObserver.onCompleted();  // rồi kết thúc lời gọi

    Phía server, lớp LookupService kế thừa LookupImplBase và ghi đè phương thức lookup. Khác với RMI, phương thức lookup không trả kết quả bằng lệnh return mà nhận thêm một đối tượng responseObserver, kiểu StreamObserver. Server gửi reply bằng phương thức onNext, rồi báo kết thúc bằng phương thức onCompleted. Lời gọi unary có đúng một lần onNext; cách viết qua StreamObserver chuẩn bị cho các lời gọi trả nhiều message ở phần sau. Ngoài đoạn mã trên slide, hàm main dùng ServerBuilder đăng ký dịch vụ ở port 9199. Hai lời gọi trong log chạy trên thread của executor mặc định trong gRPC.

    Lưu ý dựng: Mã phía trên, log phía dưới. Highlight extends LookupGrpc.LookupImplBase, rồi onNext, onCompleted theo lời đọc. Hiện dần: bước 1 khi đọc “Hai lời gọi trong log”.

    Slide 6. Client: ManagedChannel và blocking stub cho lời gọi unary

    src/main/java/netlab/grpc/LookupClient.java
    ManagedChannel channel = ManagedChannelBuilder.forAddress("127.0.0.1", 9199)
        .usePlaintext()  // HTTP/2 không mã hóa (h2c), chỉ để chạy cục bộ

LookupGrpc.LookupBlockingStub stub = LookupGrpc.newBlockingStub(channel);

    Phía client, mình tạo một đối tượng ManagedChannel để quản lý kết nối HTTP/2 tới server; phương thức usePlaintext chọn h2c, tức HTTP/2 không mã hóa như ở Chương 3, chỉ để chạy cục bộ. Trên channel đó, phương thức newBlockingStub tạo blocking stub, loại stub chặn thread gọi cho tới khi nhận được reply.     Tổng kết

    • **gRPC**: RPC trên HTTP/2; hợp đồng là **file .proto** viết bằng **Protocol Buffers**
    • **Sinh mã**: protoc tạo lớp message và stub; client gọi RPC **unary** qua **blocking stub**
    • Mã hóa theo số trường: message nhỏ hơn JSON; chỉ thêm trường mới, không đổi số trường đã dùng

    gRPC quay lại mô hình RPC, chạy trên HTTP/2, với hợp đồng là file .proto viết bằng Protocol Buffers. Từ file .proto, protoc sinh lớp message và stub, và client gọi RPC unary qua blocking stub như gọi một phương thức cục bộ. Protocol Buffers mã hóa theo số trường nên message nhỏ hơn JSON, đổi lại số trường đã dùng thì không được đổi. Phần này khép lại với sáu từ khóa: gRPC, Protocol Buffers, file .proto, sinh mã, unary và blocking stub.
