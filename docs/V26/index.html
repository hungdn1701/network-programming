    Slide 4. File .proto: dịch vụ, RPC unary và message có số trường

    • `service`, `rpc`: dịch vụ và lời gọi **unary**
    • `message`: mỗi trường có kiểu, tên và **số trường**; message lồng message
    • Không có địa danh: `name` rỗng; trường không gán mang giá trị mặc định
    src/main/proto/route_guide.proto
    service RouteGuide {
  rpc GetFeature(Point) returns (Feature) {}  // unary: một request, một response
}

message Point {
  int32 latitude = 1;  // số trường 1: định danh trường khi mã hóa, không được đổi
  int32 longitude = 2;
}
message Feature {
  string name = 1;
  Point location = 2;
}

    Khối service khai báo một RPC kiểu unary, tức một request và một response, như mọi lời gọi từ đầu chương. Hai khối message khai báo trường của Point và của Feature: mỗi trường có kiểu, tên và số trường, và trường location của Feature lại là một Point. Số trường được ghi vào tag, nên đã dùng thì không được đổi. Điểm không có địa danh được báo bằng trường name rỗng. Phiên bản 3 của Protocol Buffers không có giá trị null, trường nào không gán thì mang giá trị mặc định, như chuỗi rỗng hay số 0.

    Slide 5. Server: kế thừa lớp cơ sở sinh ra, trả kết quả qua StreamObserver

    src/main/java/netlab/grpc/RouteGuideServer.java
    static final class RouteGuideService extends RouteGuideGrpc.RouteGuideImplBase {
    @Override
    public void getFeature(Point request, StreamObserver<Feature> responseObserver) {
        responseObserver.onNext(checkFeature(request));  // unary: gửi đúng một response
        responseObserver.onCompleted();  // rồi kết thúc lời gọi
    }

    Phía server, lớp RouteGuideService kế thừa lớp cơ sở RouteGuideImplBase và ghi đè phương thức getFeature. Khác với RMI, phương thức không trả kết quả bằng lệnh return mà nhận thêm một đối tượng responseObserver, kiểu StreamObserver. Server tìm địa danh trùng tọa độ trong danh sách, gửi Feature bằng phương thức onNext, rồi báo kết thúc bằng phương thức onCompleted. Lời gọi unary gọi phương thức onNext đúng một lần, còn cách viết qua StreamObserver chuẩn bị cho các lời gọi trả nhiều message ở phần sau. Ngoài đoạn mã trên slide, hàm main dùng ServerBuilder đăng ký dịch vụ ở port 9199. Danh sách gồm tám địa danh ở Hà Nội. Hai lời gọi trong log đến từ client mình chạy ngay sau đây, và chạy trên thread của executor mặc định trong gRPC.

    • **gRPC**: RPC trên HTTP/2; hợp đồng là **file .proto** viết bằng **Protocol Buffers**
    • **Sinh mã**: protoc tạo lớp message và stub; client gọi RPC **unary** qua **blocking stub**
    • Mã hóa theo số trường: message nhỏ hơn JSON; chỉ thêm trường mới, không đổi số trường đã dùng

    gRPC quay lại mô hình RPC, chạy trên HTTP/2, với hợp đồng là file .proto viết bằng Protocol Buffers. Từ file .proto, protoc sinh lớp message và stub, và client gọi RPC unary qua blocking stub như gọi một phương thức cục bộ. Protocol Buffers mã hóa theo số trường nên message nhỏ hơn JSON, đổi lại số trường đã dùng thì không được đổi. Phần này khép lại với sáu từ khóa: gRPC, Protocol Buffers, file .proto, sinh mã, unary và blocking stub.
